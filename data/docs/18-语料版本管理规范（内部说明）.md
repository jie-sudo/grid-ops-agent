# 语料版本管理规范（内部说明）

本文档说明本项目 RAG 语料库的元数据约定与版本时效处理机制。
一、front matter 元数据字段
每篇语料文档头部有一段 YAML front matter，字段约定如下：
字段                   含义              取值
version              标准编号 / 来源       如 Q/GDW 745-2012 、 DL/T 1253-2013
status               标准状态             active （现行）/ superseded （已废止）
effective_date       生效年份            如 2012 ，未知则留空
superseded_by        替代它的新标准         标准编号，无则留空
二、为什么需要版本时效（知识冲突问题）
电网标准更新频繁，同一主题可能存在新旧多个版本。纯向量检索只认"语义相似"，<br>会把新旧两版都召回，导致大
模型在矛盾信息之间随机选择、糅合或编造，造成答案出错。
三、三层防线
1. 数据层：入库前给每篇文档标注版本号与废止状态（不删旧版，只标记，历史版本仍可查）。
2. 检索层：检索时按 status 过滤，默认只召回 active 现行标准， superseded 旧版不进上下文。
3. 生成层：prompt 约束模型——遇版本冲突优先最新版，并强制标注依据的标准编号与版本。
四、字段状态机
active（现行） ──被新标准替代──     ▶ superseded（已废止）
默认检索策略： rag_filter_superseded = true ，过滤 superseded；<br>需要查询历史版本时，可关闭过滤
（ active_only=False ）以召回全部版本。
