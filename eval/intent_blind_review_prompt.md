# 意图识别闭卷评测 · 盲审任务包

> **使用方法**：把下面「任务指令」整段复制到**全新的、干净的**会话里（每个模型各开一个，不要带任何历史对话）。让模型独立审核后输出 CSV，把 CSV 存盘发回主会话，用 `intent_compare_reviews.py` 汇总对比。
> 若目标模型无法读本地文件，请把 `intent_review_input.md` 的内容一并粘贴在 prompt 末尾。

---

## 任务指令（从这里开始复制）

你是一位意图标注审核员。请逐条审核下面的 N 条一线运维口语问句，判断每条记录里自动标注的 **意图（intent）** 是否正确。

### 一、五类定义 + 判定锚点（严格执行）

| 意图 | 一句话定义 | 判定锚点（命中即强烈倾向该意图） |
|---|---|---|
| 问答 | 问通用规程/标准/依据/周期做法，不指向某台设备此刻的异常 | 多久检修/巡视/试验/送检、按啥来、有啥讲究、多高算超/到多少算不对劲（问阈值） |
| 状态查询 | 问某台具体设备此刻的读数或状态 | 多少度/几伏/多少、合着还是断着、热不热、带多少、啥情况 |
| 异常处置 | 设备或事件出了异常，要分析原因、定级或处理 | 咋回事/啥原因/要紧不/算哪级/咋整 + 具体异常现象词（漏油/不亮/卡涩/锈了/掉/响） |
| 工单生成 | 明确要安排人去处理 | 安排人/派个活/开单/去处理掉/记一下+派人 |
| 其他 | 与电网运维无关、或不在职责范围内（家用设备、非运维事务、术语科普、无关闲聊） | 空调/冰箱/写总结/收费/科普/天气 |

### 二、三条边界规则（判 ✗ 时最常用）

1. **问答 vs 状态查询**：问「当前读数」→ 状态查询；问「阈值/标准/周期」→ 问答。
   - 「母线温度多高算超了呀」→ 问答（问阈值），不是状态查询。
2. **问答 vs 异常处置**：指向「某台设备此刻的异常怎么办」→ 异常处置；问「通用做法/周期」→ 问答。
   - 「互感器油位低了咋整呗」→ 异常处置，不是问答。
3. **异常处置 vs 工单生成**：有「安排人/派活/开单」动作 → 工单；只分析/定级/问原因 → 异常处置。

### 三、判定规则

- **判 ✗（硬依据）**：句子命中**另一意图**的判定锚点、且明显不属于标注的意图。只改这一类，不要纠结边界模糊句。
- **判 ✓（软判断）**：边界模糊、指代不清、口语省略、既像 A 又像 B 的，默认尊重标注 ✓。
- **独立判断，不要盲从标注**：标注只是参考，你有权判它错。

### 四、数据

数据文件：`F:\通用agent\grid-ops-agent\eval\intent_review_input.md`

表格列：`# / 意图（自动标注） / 口语问句 text`

### 五、输出要求（严格遵守）

只输出一个 CSV，**不要任何解释、前言、寒暄、markdown 代码块围栏**。格式如下：

```
意图,序号,text,判定,纠正
问答,1,断路器一般多会儿检修一回啊？,✓,
问答,2,母线温度多高算超了呀？,✓,
异常处置,5,互感器油位低了咋整呗？,✗,异常处置
```

- **判定列**：只填 `✓` 或 `✗`。
- **纠正列**：✓ 留空；✗ 填**正确意图**（问答/状态查询/异常处置/工单生成/其他之一），无法归类的填 `删除`。
- 必须完整输出所有行，顺序与输入一致，不要漏行、不要合并。
- **独立判断**，不要受任何已有结论或第三方审核结果影响。

## 拿到各模型 CSV 后的汇总命令

```bash
cd F:\通用agent\grid-ops-agent\eval
python intent_compare_reviews.py modelA.csv modelB.csv modelC.csv
```

将输出：两两一致率 / 逐条分歧清单 / 共识判✗条目 / 各模型✓✗统计。

若还没有输入文件，先跑：

```bash
python intent_compare_reviews.py --make-input
```
