# 意图识别踩坑记录

> 主题：意图识别从「关键词规则」到「五类 + LLM few-shot 兜底」的完整踩坑过程。
> 核心教训：**意图是软先验，不该当硬分类器做；关键词规则在口语下是纸糊的；意图识别的坑，评测的比实现的多。**

---

## 背景

意图路由：`IntentRouter.route`（规则优先 + LLM 兜底），意图是「软先验、不锁工具」——分错不致命，ReAct 循环会兜回来。原为七类：问答/状态查询/告警分析/缺陷分级/故障诊断/工单生成/其他。SRS 验收目标：意图 ≥700 条样本。

---

## 坑 1：规则层在闭卷口语下「0% 精确率」，还以 0.9 置信抢跑

早期规则层用关键词（缺陷/告警/诊断/故障/温度/电流…），命中即返回 `(intent, 0.9)`、直接短路跳过 LLM。开卷评测（带关键词的规范问句）看着还行。

**真相**：用「不带触发关键词」的闭卷口语评测，规则层覆盖率 5.8%、**命中的 8 条全错（精确率 0%）**。而且最要命的是它抢跑——`变压器有缺陷按规矩咋整`（真值=问答）被「缺陷」钩成缺陷分级，`这个告警咋整，安排人去处理`（真值=工单）被「告警」钩成告警分析。

**教训**：关键词规则要像分类器特征一样做「精确率审计」，不能凭直觉堆词。「缺陷」「告警」「温度」这种宽泛词单独出现根本定不了意图。规则层应该只留高精确的动作词（工单/派单/开单），其余交 LLM。

---

## 坑 2：七类并五类——先改「分类学」再调模型

七类里「告警分析 / 故障诊断 / 缺陷分级」三个类在口语里天然重叠：混淆矩阵显示告警 10/17 被吞进故障诊断、缺陷 7/17 被吞进故障诊断。「变压器跳闸了咋回事」告警、诊断、缺陷三沾边。

**真相**：这不是 LLM 笨，是分类边界本身糊。把三个类合并成「异常处置」后，这 17 条「误判」全部变成正确，准确率 +12pp（65.9% → 78%）。内部再分「告警 vs 诊断 vs 定级」的责任交给 ReAct 工具调度，比交给前置分类器靠谱。

**教训**：分类不准时，先怀疑分类体系，别急着调模型或堆规则。**加 agent 也解决不了边界模糊**——多一个 agent 不改变歧义，只改变谁在犯错。

---

## 坑 3：few-shot 格式不一致 → 静默降级（最隐蔽的 bug）

给 LLM 兜底加了 few-shot 样例，但样例的 assistant 回复写成了裸意图词（`问答`），而 system 要求「只输出 JSON」。结果准确率不升反降：91.3% → 43.5%，73 条被扔进「其他」。

**真相**：模型照着 few-shot 学，输出裸的 `问答` 而不是 `{"intent":"问答"}`，`chat_json` 解析失败抛 `LLMError`，被 `route()` 静默吞掉、兜底成「其他」。**它不报错，只是悄悄把准确率打下去。**

**教训**：few-shot 的样例回复格式**必须**和你要求模型输出的格式一致（这里是 JSON）。这是 LLM 应用里最容易骗过人的坑——静默降级没有报错，只有数字下滑。

---

## 坑 4：LLM 失败静默伪装成「其他」

`route()` 把 `LLMError` 静默映射成 `("其他", 0.5)`。网络抖动时，大量 LLM 调用失败，全部伪装成「其他」，一轮评测的准确率能从 91% 掉到 43%，**而且看不出来**。

**真相**：评测脚本和 `route()` 都分不清「LLM 失败」和「真判成其他」。生产上这是颗雷——意图分类静默降级成「其他」，用户看到的是「系统以为我在闲聊」。

**教训**：静默降级要有计数 + 告警日志。已加 `llm_failures` 计数 + warning 日志，评测脚本会显示「LLM 调用失败 N 次」，N>0 就说明这轮数字不可信。

---

## 坑 5：「其他」类注水，98.6% 是假高分

评测集里「其他」类全是「今天天气」「中午吃啥」这种一眼垃圾，召回 98.6%——但把一个明显无关的闲聊拒掉，任何模型闭着眼都能做到。

**真相**：「其他」类真正该测的是「领域擦边但该拒」的硬样本：家用设备（我家空调不制冷）、非运维事务（帮我写总结）、术语科普（变压器是干啥用的）。这些才考验兜底类能不能挡住「听起来沾边、其实不该接」的输入。

**教训**：评测集里的负样本要测「难的那部分」，不是测闭眼都能对的。否则高分是注水的，对应安全兜底（不该接的不乱答）等于没验证。

---

## 坑 6：生成器-评估器同源，96.3% 是乐观上界

评测集是「一个 LLM 生成、一个 LLM 标注、同一个 LLM 评测」，96.3% 里有多少是自嗨水分，不换第三方审量不出来。

**真相**：用三模型盲审（DeepSeek / GLM5.2 / MiniMax，两两一致率 99.3%~99.9%）交叉审核，发现标注 **~98% 可信**，且噪声 **100% 集中在「问答→异常处置」**这一种错误——生成 LLM 把「油位低了咋整」「带电显示不亮咋弄」这些具体异常错标成了问答。纠正 12 条后重跑，准确率 96.8%。

**教训**：自产自评的数字要打折。多模型盲审（A 类硬依据 / B 类软判断 + 共识判 ✗）能把「要人工看的」从 728 条缩到 10-15 条，是打破同源偏差最省力的办法。

---

## 坑 7：样本量靠 seed 不靠 variants，重复注水

早期生成脚本「改写 42 个固定 seed + `--variants 3`」，堆到 138 条，但 `SF6气体漏了该咋整啊？` 一模一样的句子出现 3 遍——温度 0.5 挡不住 LLM 输出重复。

**真相**：138 条里一半是重复，等于 300 条不到的有效样本。改成「LLM 直接批量生成 + 强制不重复 + 归一化去重」后，才真冲到 728 条且不注水。

**教训**：样本量要看「去重后的有效条数」，不是文件行数。堆 variants 只会堆重复；要多样性得扩 seed 库 + 强制不同 + 去重。

---

## 结论

意图识别最终：**五类（问答/状态查询/异常处置/工单生成/其他）+ 规则层收缩 + LLM few-shot 兜底**，728 条闭卷口语评测集（多模型盲审过），准确率 **96.8%**、LLM 失败 0 次，五类召回 ≥94%。规则层只剩「温度/电流」残留词的少量误判（下一步删）。

意图识别和缺陷分级踩的是同一类坑：**确定性规则在真实口语下是纸糊的，评测的坑（开卷自嗨、同源、静默降级、负样本注水）比实现的坑多得多。**
