# RAG 检索技术说明

> 电网智能运维 Agent 的知识库检索子系统的完整技术说明，覆盖从原始 PDF 到可检索、
> 可定级知识库的全链路，含关键技术决策、实测指标与踩坑记录。
> 相关文档：《知识库切分踩坑记录.md》（5 个坑）、《历史数据保留与复盘案例库设计.md》。

---

## 1. 概述

把 101 个电力标准/导则/案例 PDF（1.1GB，含 62 个扫描件）构建成可检索知识库，并支撑两件事：

1. **RAG** 问答：自然语言问题 → 检索相关条款 → LLM 生成带出处的答案；
2. **确定性缺陷定级**：缺陷描述 → 匹配结构化缺陷库 → 输出等级（不经过 LLM）。

最终检索指标（300 题生成集）：**Recall@5 = 89.7%，Recall@10 = 94.0%**（混合检索 + rerank 精排）。

---

## 2. 整体架构

```
                     ┌─ RAG 构建（离线，一次）────────────┐
101 PDF ──OCR──清洗──切分──向量化──ChromaDB（7107 chunk）
   │
   └─ 结构化抽取（离线，一次）── 缺陷库（5964 条）── 规则引擎定级

                     ┌─ 检索（在线，每次问答）────────────┐
问题 ──混合召回(向量+关键词 RRF, top-30)──rerank 精排(top-5)──LLM 生成
```

关键分层：**RAG 解决"查得到"，结构化缺陷库解决"判得准"**。前者的答案由 LLM 生成（有幻觉风险，靠溯源兜底）；后者的定级是确定性规则（LLM 不参与）。

---

## 3. 语料与 OCR 层

**语料**：知识星球「电力图书馆」下载的 101 个文件（1.1GB）——98 个 PDF（36 文字版 + 62 扫描件）+ 1 doc + 1 ppt + 1 pptx。核心是缺陷分类标准（Q/GDW 745 配电网、Q/GDW 1906 输变电）、状态评价/检修导则、安规、故障案例汇编。

**OCR 分两条路**：

| 内容 | 方案 | 原因 |
|---|---|---|
| 扫描件正文 | 本地 PaddleOCR（CPU） | 免费；paddlepaddle 3.2.1 + PP-OCRv6_small + oneDNN 提速 |
| 复杂表格（1906 缺陷库表） | 百度智能云「表格文字识别」 | 本地 OCR 对合并单元格表格打碎成"绝缘电阻不\n合格"，商用 OCR 返回单元格+行列坐标 |

> 表格 OCR 的关键教训：**纯文本 OCR 对表格无能为力**，必须用返回单元格结构的表格识别，才能重建对齐的二维表。为此我们把 1906 的 347 页表格用商用 OCR 重做，替换本地碎片。

---

## 4. 清洗层（去噪）

扫描件 OCR 出来带大量噪声，清洗规则（`app/data/ocr_clean.py`，纯函数）：

- 整页丢弃：知识星球广告页、封面/版权页、目次页；
- 逐行丢弃：每页水印（"电力图书馆知识星球"）、页眉（跨页重复的无中文短行）、页码、OCR 乱码（无中文+连续字母）。

**5 个坑**（详见《知识库切分踩坑记录.md》），最有代表性的是：**页眉去重误删了"a）危急缺陷"这类等级标记**——因为"重复出现"不等于"页眉"，区分标准是"有没有中文"。

---

## 5. 切分层（语义切分）

切分原则（`app/data/kb.py` 的 `chunk_structured`）：

1. **语义完整**：按章节边界切，一个 chunk 是一个完整章节/部位；
2. **上下文自足**：块头带完整章节路径（`4 缺陷分类 / 4.1 架空线路 / 4.1.1 杆塔 / 4.1.1.1 杆塔本体`）；
3. **粒度对齐嵌入上限**：正文 ≤400 字 + 块头 ≈500 字，贴着 bge-small-zh 的 512 token 上限——**超过会被静默截断**；
4. **不混类**：危急/严重/一般阈值放一起（供定级比较），大块时按等级软边界切开。

**切分质量指标**：孤儿块 0、带章节路径 98.7%、超过嵌入上限仅 4.1%。

---

## 6. 向量化与嵌入模型选型

用 6 个中文嵌入模型在同一套 300 题上对比，结论**反直觉但明确：bge-small 最优，越大越差**：

| 模型 | 混合 R@5 | 结论 |
|---|---|---|
| **bge-small-zh-v1.5**（选用） | **80.8%** | 最快，效果最好 |
| bge-base-zh-v1.5 | 76.9% | 更大反而更差 |
| bge-large-zh-v1.5 | 73.1% | 更大更差 |
| bge-m3（8192 token） | 76.9% | 长文本但混合无加成 |
| m3e-base | 73.1% | 不匹配语料 |
| text2vec-base | 80.8% | R@10 不如 small |

**原因**：语料是"电力专业术语 + OCR 噪声"，大模型通用语义强但对噪声文本"想多了"；且纯向量越强，关键词路的补充空间越小。

---

## 7. 检索层（混合召回 + 加权 RRF + rerank）

三段式检索链路，每段都是数据验证过的：

**7.1 混合召回**：向量（bge-small 余弦）+ 关键词（中文字符 bigram 匹配），RRF 倒数排名融合。

**7.2 加权 RRF**：给关键词路更高权重（`weights=[1.0, 2.0]`）。归因发现等权融合时，"关键词精确命中但向量排几百名"的 chunk 被向量噪声淹没——加权后召回 miss 从 11 题降到 4 题。

**7.3 rerank 精排**：交叉编码器（bge-reranker-base）对召回 top-30 精排取 top-5。融合公式：

```
最终分 = sigmoid(交叉编码器分) + keyword_weight × 关键词命中分
```

关键词项是通用保护——归因发现 rerank 曾把"混合排第 1 的正确 chunk"排下去 5 次，关键词保护修正了这个误判。

**逐段效果**（300 题）：

| 阶段 | R@5 | R@10 |
|---|---|---|
| 纯向量 | 69.2% | — |
| 混合检索 | 73.3% | 83.3% |
| + 加权 RRF + rerank | **89.7%** | **94.0%** |

## 8. 结构化知识抽取（跳出 RAG）

从缺陷分类标准抽取**结构化缺陷库（5964 条）**，接入规则引擎定级：

| 库 | 来源 | 条数 | 定级方式 |
|---|---|---|---|
| 配电网 | Q/GDW 745 | 576 | 缺陷描述含阈值（"倾斜≥3%"=危急） |
| 输变电 | Q/GDW 1906 | 5388 | 缺陷描述 + 分类依据（basis） |

定级链路：**关键词规则 → 缺陷库匹配兜底**。安全约束：**只有匹配到单一等级才定级，多个等级歧义则降级人工复核**（绝不默认"一般"）。

这体现了项目的核心原则 C1：LLM 仅编排，确定性计算走规则。

**设备域筛选（避免跨库歧义）**：745（配电网）和 1906（输变电）对同一缺陷现象定级不同（如"无法储能"：745 严重、1906 危急），合并匹配会产生跨库歧义导致降级。解法：定级工具接收 `device_type`（设备粗类关键词），在缺陷库匹配前按设备字段做子串过滤——"断路器"只匹配断路器记录（危急）、"柱上"只匹配柱上开关记录（严重）。设备类型从**会话锚点确定性获取**（DEV→device_type），不进 prompt、不靠 LLM。三档兜底：有设备类型才筛选、过滤空回退全库、无设备保持歧义降级。

**匹配方式（压测验证）**：缺陷库定级用**字符 bigram 字面匹配**，不用嵌入语义匹配。压测 500 样本：bigram 命中率 71%、误判 0；嵌入匹配命中率仅 2%（语义相似度把"绝缘电阻不合格"vs"电容量不合格"等细微差异抹平，导致跨等级歧义降级）。**原因**：电力缺陷是规范化术语、字面即标准，且定级需精确区分"无法继续运行（危急）vs 可短期维持（严重）"这类细微但致命的差异。嵌入语义匹配的正确用途是"口语化输入归一化"（把"好像漏油了"归一到"渗油"），属于输入层、不是定级层。

---

## 9. 评估体系

三层评估，避免"拍脑袋说准确率"：

1. **结构性指标**（自动算）：孤儿块、带路径比、超嵌入上限比；
2. **Recall@K**（检索命中率）：问题 → 正确 chunk 是否在 top-K；
3. **miss 归因**（`analyze_miss.py`）：把 miss 拆成"召回 miss / 排序 miss"，定位是粗排问题还是精排问题。

评估集：**26 人工题（闭卷）+ 2375 生成题（从缺陷库自动生成，开卷有偏）**。

**关键认知**：生成集绝对 Recall（89.7%）偏乐观，真实用户口语问题会更低，对外应表述为"检索命中率 89.7%（生成集）/ 80%~85%（估计真实）"，不要混用"准确率"。

---

## 10. 关键结论（数据验证过的，可直接引用）

1. **嵌入模型不是越大越好**——bge-small + 混合检索最优（80.8%），换大模型反而降到 73%~77%；
2. **混合检索比纯向量强 11~15 个点**——精确字面匹配必须有关键词路；
3. **加权 RRF 救回"关键词命中但被向量淹没"的 chunk**——召回 miss 11→4；
4. **rerank 精排再 +5 个点**（84.7→89.7），但需关键词保护防止误排；
5. **表格必须用商用/结构化 OCR**，纯文本 OCR 对表格无能为力；
6. **结构化缺陷库是"确定性知识"，和 RAG 是两件事**——前者定级不靠 LLM，后者答案靠 LLM 但靠溯源兜底；
7. **设备域是确定性筛选，不是 prompt 内容**——用设备类型子串过滤缺陷库记录消除跨库歧义，prompt 零改动、LLM 零参与。
