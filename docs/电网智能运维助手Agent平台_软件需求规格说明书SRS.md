## 1 引言

### 1.1 编写目的

本文档定义"电网智能运维助手 Agent 平台"的完整软件需求，作为后续**设计、开发、测试、验收**的统一依据。所有需求均编号，可追踪、可测试。

读者对象：项目开发者、测试人员、评审人员及合作方（第三方运维/设备厂商）。

### 1.2 项目背景

电网运维向"状态检修"转型，但存在：诊断能力不足（数据采集率 >90%、有效诊断率 <40%）、数据孤岛、缺乏跨设备统一评估模型、人才缺口、过程不可追溯等痛点。本平台以"通用 Agent 引擎 + 统一数据模型 + 可插拔技能包"方式，辅助运维人员完成问答、诊断、缺陷分级、告警分析、工单生成等环节。

### 1.3 术语与缩略语

| 术语 | 说明 |
|------|------|
| Agent | 具备"理解—规划—调用工具—生成结论"能力的智能体 |
| ReAct | "推理—行动—观察"主控循环 |
| RAG | 检索增强生成 |
| 技能包（Skill Pack） | 某类设备/业务的可插拔工具与规则集合 |
| 缺陷三级 | 一般 / 严重 / 危急 |
| 状态四态 | 正常 / 注意 / 异常 / 严重 |
| LLM | 大语言模型（可替换，默认 DeepSeek） |

### 1.4 参考资料

| 编号 | 名称 |
|------|------|
| R1 | GB/T 8567 计算机软件文档编制规范 |
| R2 | IEEE 830-1998 软件需求规格说明书 |
| R3 | Q/GDW 644 / 645 / 745 配网设备状态检修/评价/缺陷分类标准 |
| R4 | GB 26860 电力安全工作规程 |
| R5 | DL/T 596 电力设备预防性试验规程 |

### 1.5 需求范围

本平台覆盖：**知识问答、设备状态查询、告警分析、缺陷分级、故障诊断（可插拔）、工单生成** 六大业务能力，以及支撑它们的通用 Agent 引擎、统一数据模型、知识库与对外接口。

**范围与优先级说明**：六大业务能力的**核心路径**（问答、查询、告警、缺陷分级、诊断、工单草稿与二次确认）为 P0 本期必交付；**增强项**（状态评价 FR-022、隐患督办 FR-042、工单验收的完整流转）为 P1 本期尽力交付。P1 未完成不影响"六大能力"作为平台能力框架的完整性。

**本期不包含**：控制类操作（遥控/遥控开关）、多模态巡检图像识别、真实生产系统接入（以模拟数据验证，预留接口）。

## 2 总体描述

### 2.1 产品定位

通用运维 Agent 引擎：**框架通用、场景插件化**。引擎与数据模型复用，设备/场景通过技能包接入。

### 2.2 用户角色与特征

| 角色 | 特征 | 主要目标 |
|------|------|---------|
| 运维人员 | 具备电力基础知识，需快速查询与研判 | 查规程、判缺陷、得诊断与处置建议 |
| 值班/监控人员 | 需快速解读告警、排优先级 | 告警研判、处置建议 |
| 计划/管理人员 | 关注台账与闭环 | 缺陷台账、消缺计划、督办 |
| 系统管理员 | 具备 IT 能力 | 知识库管理、配置、审计 |

### 2.3 运行环境

| 项 | 要求 |
|----|------|
| 操作系统 | Linux（服务器）/ 跨平台（开发） |
| 运行语言 | Python 3.11+ |
| 对外服务 | FastAPI（REST） |
| 存储 | SQLite/PostgreSQL（结构化）+ 向量库（ChromaDB/FAISS） |
| LLM 服务 | OpenAI 兼容接口（DeepSeek，可替换） |

### 2.4 设计约束与假设

- C1：LLM 仅负责**编排与解释**，诊断/分级等确定性计算必须由规则/算法完成。
- C2：写操作（工单落库）必须**二次确认**。
- C3：诊断在数据不足或超出规则适用条件时，**必须降级为"建议人工复核"**，禁止编造。
- C4：现阶段数据为模拟/公开数据；外部系统对接采用适配器模式预留。

### 2.5 交付物

源代码、本 SRS、系统设计文档、测试用例与评估报告、运行部署说明、演示 Demo。

### 2.6 等级体系与映射

**BR-001 等级体系总览**：本平台存在四套等级，需明确映射关系，避免业务贯通时歧义：

| 体系 | 等级（由轻到重） | 维度 |
|------|----------------|------|
| 告警等级 | 提示 / 重要 / 紧急 | 事件紧迫度 |
| 缺陷等级 | 一般 / 严重 / 危急 | 设备缺陷危害 |
| 状态四态 | 正常 / 注意 / 异常 / 严重 | 设备健康度 |
| 工单等级 | 一般 / 严重 / 危急 | 沿用缺陷等级 |

**映射规则（默认，可人工修正）：**

**BR-002 告警 → 缺陷**（仅当告警经确认反映设备缺陷时生效；一过性/误报告警不产生缺陷）：

| 告警等级 | 默认缺陷等级 |
|---------|------------|
| 紧急 | 危急 |
| 重要 | 严重 |
| 提示 | 一般 |

**BR-003 状态四态 → 缺陷**（状态评价结果与缺陷的对应）：

| 状态 | 应有缺陷情况 |
|------|------------|
| 严重 | 存在危急缺陷（或等效异常） |
| 异常 | 存在严重缺陷 |
| 注意 | 可能存在一般缺陷，需加强监视 |
| 正常 | 无缺陷或仅一般缺陷（可控） |

**BR-004 工单等级**：由缺陷生成时 = 缺陷等级；由告警直接生成时 = 告警映射后的缺陷等级。

**BR-005 消缺时限**：由缺陷等级决定——危急 ≤24h、严重 ≤30 天、一般列入计划。

**BR-006 冲突处理**：同一设备同时存在多等级信号时，**取最高等级（从严）**；映射为默认规则，允许有依据的人工修正并记录理由。

## 4 功能需求（FR）

> 每个用例按统一模板描述：优先级 / 触发条件 / 前置条件 / 输入 / 处理流程 / 输出 / 异常处理 / 验收标准。

### 4.1 通用 Agent 引擎

#### FR-001 意图路由
- **优先级**：P0
- **触发条件**：用户提交一次对话请求
- **前置条件**：系统启动，引擎加载完成
- **输入**：用户自然语言文本
- **处理流程**：对文本进行分类，映射到 {问答、状态查询、告警分析、缺陷分级、故障诊断、工单生成、其他} 之一；分类置信度低于阈值时进入澄清流程
- **输出**：意图标签 + 置信度；低置信度时输出澄清提问
- **异常处理**：无法识别 → 输出引导式澄清，不终止
- **验收标准**：七类意图（六大业务 + "其他"兜底）识别准确率 ≥ 90%（样例评估集）

#### FR-002 ReAct 主控循环
- **优先级**：P0
- **触发条件**：意图确定后
- **处理流程**：执行"推理 → 调用工具 → 观察结果 → 再推理"循环；最大步数 6；达到上限或模型输出最终结论时终止
- **输出**：最终结论文本
- **异常处理**：超步数 → 输出"请细化问题"并提示可补充信息
- **验收标准**：单任务在步数上限内完成；死循环率为 0

#### FR-003 工具调度
- **优先级**：P0
- **输入**：模型返回的工具名 + 参数
- **处理流程**：按工具注册表校验名称与参数 schema；参数非法返回错误说明；执行并序列化结果回填对话
- **输出**：工具执行结果（结构化）
- **异常处理**：工具不存在/参数错误/执行超时 → 返回结构化错误，不抛原始堆栈
- **验收标准**：非法调用 100% 被拦截并回填可读错误

#### FR-004 二次确认闸口
- **优先级**：P0
- **触发条件**：任何写操作（工单落库）被触发
- **处理流程**：生成操作预览 → 请求用户确认（确认/取消）→ 仅确认后执行
- **输出**：确认提示 + 执行结果
- **异常处理**：用户取消 → 丢弃写操作并记录
- **验收标准**：写操作二次确认覆盖率 100%

#### FR-005 评估与追溯记录
- **优先级**：P1
- **处理流程**：每次会话记录完整工具链、引用来源、耗时、是否降级，写入追溯日志
- **验收标准**：每次诊断/问答可回溯完整调用链

### 4.2 知识问答（RAG）

#### FR-010 知识检索
- **优先级**：P0
- **输入**：用户问题
- **处理流程**：向量化 → 检索 top-k → 按设备域/标签过滤 → 重排
- **输出**：候选文档片段列表（含来源）
- **验收标准**：单库 1000 篇文档检索响应 < 2s

#### FR-011 带出处回答
- **优先级**：P0
- **处理流程**：基于检索片段生成答案；**必须附出处（规范编号/文档标题/章节）**；无相关片段时明确回答"未检索到依据"
- **异常处理**：检索为空 → 不编造，提示无依据
- **验收标准**：答案引用准确率 ≥ 90%，无依据编造率 < 1%

#### FR-012 知识库管理
- **优先级**：P1
- **输入**：文档（规程/案例/处置卡）
- **处理流程**：解析 → 切片 → 打标签（类型/设备域）→ 向量化入库
- **输出**：入库状态与文档 ID
- **验收标准**：入库文档可被检索命中

### 4.3 设备状态查询

#### FR-020 台账查询
- **优先级**：P0
- **输入**：设备编号/名称
- **输出**：设备台账（类型、电压等级、站所、投运日期、额定参数、状态）
- **异常处理**：设备不存在 → 提示核对编号
- **验收标准**：查询准确率 100%

#### FR-021 量测查询
- **优先级**：P0
- **输入**：设备 + 量测类型 + 时间范围
- **输出**：实时值 + 历史序列 + 阈值对照
- **验收标准**：返回数据与数据源一致

#### FR-022 状态评价查询
- **优先级**：P1
- **输入**：设备编号
- **处理流程**：按状态评价规则（Q/GDW 645 思路）综合量测与缺陷，输出四态（正常/注意/异常/严重）及依据
- **验收标准**：评价结果含依据，可追溯

### 4.4 告警分析

#### FR-030 告警查询
- **优先级**：P0
- **输入**：设备/时间范围/告警类型
- **输出**：告警列表（类型、等级、时间、关联量测）

#### FR-031 告警等级判定
- **优先级**：P0
- **处理流程**：按告警类型与越限程度映射等级（提示/重要/紧急）
- **输出**：等级 + 判定依据

#### FR-032 告警处置建议
- **优先级**：P1
- **处理流程**：结合告警等级、设备状态、知识库预案，生成处置优先级与建议
- **验收标准**：建议含依据，紧急告警优先标注

### 4.5 缺陷识别与分级

#### FR-040 缺陷等级判定
- **优先级**：P0
- **输入**：缺陷描述/量测数据
- **处理流程**：按分级规则（见附录 A）判定一般/严重/危急
- **输出**：缺陷等级 + 分级依据
- **验收标准**：分级准确率 ≥ 95%（带标签评估集）

#### FR-041 消缺时限计算
- **优先级**：P0
- **处理流程**：按等级映射时限——危急 ≤24h、严重 ≤30 天、一般列入计划
- **输出**：消缺时限
- **验收标准**：时限映射正确率 100%

#### FR-042 隐患督办
- **优先级**：P1
- **处理流程**：危急缺陷超 24h 未消缺 → 标记为"隐患"并纳入督办
- **验收标准**：超时缺陷 100% 被标记

### 4.6 故障诊断（可插拔）

#### FR-050 技能包加载
- **优先级**：P0
- **处理流程**：按设备类型加载对应技能包（查询工具 + 诊断规则 + 阈值表 + 专属知识）
- **验收标准**：至少 2 个设备类型技能包可加载，切换场景不改引擎

#### FR-051 诊断执行
- **优先级**：P0
- **输入**：设备 + 量测数据
- **处理流程**：调用技能包诊断规则（确定性算法）计算 → 输出故障类型、置信度、数据依据
- **验收标准**：诊断结论 100% 附数据来源

#### FR-052 诊断降级
- **优先级**：P0
- **处理流程**：数据不足、超出规则适用条件（如湿度超限）→ 降级输出"建议人工复核"，不输出确定性诊断
- **验收标准**：不满足条件时 100% 降级，0 编造

### 4.7 工单生成

#### FR-060 工单草稿生成
- **优先级**：P0
- **输入**：诊断/缺陷结论
- **处理流程**：生成结构化工单草稿（内容、部位、等级、时限、建议措施、负责人）；**"建议措施"字段若由 LLM 生成，必须附来源依据（引用知识库/规程）；无法附依据时，标注"待人工确认"**
- **输出**：工单草稿（待确认）
- **验收标准**：字段完整率 100%；建议措施字段 100% 附来源或标注"待人工确认"

#### FR-061 工单二次确认
- **优先级**：P0
- **处理流程**：展示草稿 → 用户确认/修改/取消
- **验收标准**：未经确认不落库

#### FR-062 工单落库与闭环
- **优先级**：P0（核心：落库 + 关联缺陷）/ P1（增强：验收状态完整流转）
- **处理流程**：确认后落库；工单关联缺陷；支持验收状态流转
- **验收标准**：缺陷—工单—验收全链路可追溯（核心路径 P0 必验）

## 5 接口需求（IF）

| 编号 | 接口 | 方向 | 协议/格式 | 说明 |
|------|------|------|-----------|------|
| IF-001 | 数据接入层 | 入 | 适配器（CSV/JSON，预留 PMS/监测系统） | 统一转换为内部数据模型 |
| IF-002 | LLM 服务 | 出 | OpenAI 兼容 REST（DeepSeek） | 可替换模型 |
| IF-003 | 向量库 | 双向 | ChromaDB/FAISS | 知识切片入库与检索 |
| IF-004 | 对外服务 | 出 | FastAPI REST + JSON | 供 Web/第三方调用 |

**接口通用要求**：
1. 所有入参校验，异常返回统一结构 `{code, message, data}`。
2. **鉴权**：JWT（HS256），`role` 声明角色；接口层按 RBAC 校验操作权限。
3. **错误码枚举**：`0` 成功、`400` 参数错误、`401` 未认证、`403` 无权限、`404` 不存在、`429` 限流、`500` 内部错误、`504` 上游超时。
4. **超时/重试**：LLM 调用超时 30s、重试 1 次；工具执行超时 10s 不重试。
5. **限流**：演示级每用户 60 次/分钟；写接口 10 次/分钟。
6. **RBAC 落地**：接口与操作一一对应，权限矩阵见第 8 章；写接口需二次确认（见 FR-004）。

## 6 数据需求（DR）与数据字典

### 6.1 数据模型关系

```
Device 1 ── n MeasurePoint（测点定义）
MeasurePoint 1 ── n MeasureValue（时序数据）
Device 1 ── n Defect
Device 1 ── n Alarm
Defect/Alarm 1 ── 1..n WorkOrder（可关联）
KnowledgeDoc（独立，按 device_domain 关联）
```

### 6.2 数据字典

> 类型：S=字符串，N=数值，DT=日期时间，E=枚举，JSON=对象。约束：PK=主键，FK=外键，NN=非空。

#### DR-001 Device（设备）

| 字段 | 类型 | 长度 | 约束 | 取值范围/说明 |
|------|------|------|------|--------------|

## 10 评估集与验收方法

### 10.1 评估集构建

| 指标 | 样本来源 | 样本量 | 标注规则 |
|------|---------|--------|---------|
| 意图识别准确率 | 模拟数据 + 人工构造 | ≥700 条（7 类各 ≥100） | 人工标注意图标签 |
| 缺陷分级准确率 | 模拟数据按"注入模式"生成 | ≥200 条（三等级 + 边界） | 生成即带标签，抽样 20% 人工复核 |
| 问答引用准确率 | 规程文档人工构造 Q/A | ≥100 对 | 人工标注正确引用出处 |
| 编造率 | 库外问题（知识库确无依据）+ 问答/诊断样本 | ≥50 条库外问题 | 见 10.2 判定规则 |
| 可追溯率 | 诊断/工单评估集 | ≥50 条 | 人工核对结论与来源对应 |

**抽样与隔离**：按类别分层抽样；评估集与开发/调优数据**不重叠**；评估结果可复现（固定随机种子 + 版本化数据）。

### 10.2 关键指标判定标准

- **意图识别准确率**：模型输出意图与人工标签一致即为正确。
- **缺陷分级准确率**：分级结果与注入标签一致即为正确。
- **问答引用准确率**：答案中每处引用均能对应到真实存在的知识片段即为正确引用。
- **无依据编造率**：答案或结论中，**既不在检索片段、也不在工具返回数据中**的事实性陈述记为"编造"；编造率 = 编造样本数 / 总样本数。纯解释性语言、格式性语言不计入编造。
- **可追溯率**：结论中关键论断能对应到工具返回数据或知识片段来源的比例。
- **死循环率**：单任务超过步数上限或重复调用同一工具且无进展即记一次死循环。

### 10.3 验收通过准则

各指标达到第 4 章、第 7 章量化值，且评估集规模达标；未达标项在评估报告中逐项说明并给出整改计划。

### 10.4 验收标准（汇总）

| 序号 | 验收项 | 标准 |
|------|--------|------|
| 1 | 六大业务能力可用 | 问答/查询/告警/缺陷/诊断/工单全流程跑通 |
| 2 | 缺陷分级 | 准确率 ≥95%，时限正确 |
| 3 | 诊断可追溯 | 结论 100% 附来源，数据不足正确降级 |
| 4 | 工单安全 | 二次确认 100%，闭环可追溯 |
| 5 | 通用性 | ≥2 个技能包，切换不改引擎 |
| 6 | 评估报告 | 提供量化指标与样例评估集 |
