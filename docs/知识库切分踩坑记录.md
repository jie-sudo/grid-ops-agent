# 知识库 OCR 清洗与切分 · 踩坑记录

> 记录把 101 个电力标准/导则 PDF（知识星球下载，1.1GB）做成可检索知识库的过程中，
> 在「清洗 → 切分 → 入库」环节踩过的坑。每个坑按 **现象 → 根因 → 修复 → 教训** 记录。
> 配套脚本：`app/data/ocr_clean.py`（清洗）、`app/data/kb.py`（切分 + 指标）、
> `scripts/chunk_quality_report.py`（切分质量报告）、`scripts/eval_retrieval.py`（Recall@K 评测）。

---

## 背景

流程是：OCR 扫描件 → 清洗（去广告/水印/乱码）→ 结构切分 → 灌 ChromaDB。
嵌入模型是 `BAAI/bge-small-zh-v1.5`，**max 长度 512 token（中文约 500 字）**——这条是后面好几个坑的总根源。

---

## 坑 1：清洗误删了"危急/严重/一般"等级标记（最严重）

**现象**：结构切分后抽查 chunk，发现 `a）危急缺陷`、`b）严重缺陷`、`c）一般缺陷` 这些等级标记**消失了**，只剩光秃秃的条目。等级标记是缺陷定级的命根子，删了等于抹掉"危急/严重/一般"的分界线。

**根因**：清洗里有个"页眉去重"——把**跨页重复出现的短行**当页眉删掉。而 `a）危急缺陷` 又短、又在每个章节都出现，于是被当成页眉误删。

**修复**：页眉去重只针对**没有中文**的短行（标准号 `Q / GDW 745 — 2012` 这种），有中文的重复行保留。

```python
# 修复后：只有无中文的短行才参与"页眉去重"统计
if s and len(s) <= 60 and not has_cjk(s):
    header_counts[s] += 1
```

**教训**：**"重复出现"不等于"页眉"**。正文里大量合法内容会跨页重复（等级标记、表头、固定句式）。区分页眉和正文的关键特征是"有没有中文"，不是"重不重复"。

## 坑 2：水印被当成广告页，整页误删 → 文档洗成空

**现象**：安规（`DL/T 408-2023`，41 页）清洗后**一个字都不剩**。

**根因**：广告页检测写的是"页里含『星球』就整页丢"。但有些文件没有单独广告页，而是在**每一页**都盖了水印「电力图书馆知识星球」——于是 41 页全被当成广告页删光。

**修复**：把"广告页"和"水印"分开处理：

- **广告页（整页丢）**只用强特征：`长按 / 二维码 / 独家精华 / 已有9999 / 上万份 / 资源合集`；
- **水印「电力图书馆知识星球」（逐行丢）**：只删这一行，不删整页。

**教训**：**同一个词出现在"广告页"和"每页水印"里，处理粒度必须不同**。判断"整页丢"要用只在广告页出现的强特征，不要用一个词去同时覆盖两种场景。

---

## 坑 3：超长块 + 嵌入模型静默截断（性能坑）

**现象**：切分质量报告显示 **37% 的块超过 700 字**，集中在缺陷分类标准（Q/GDW 1906 有 358 页）、事故案例汇编这类大章节文档。

**根因**：两层问题叠在一起：

1. 固定 700 字上限，对"一个缺陷部位十几个条目"的大章节太小，被硬拆；
2. 更致命的是——**700 字本身就超了嵌入模型上限**。`bge-small-zh-v1.5` 是 512 token（中文约 500 字），超出的部分会被**静默截断**，也就是说之前那些"超长块"一直在丢着后半段入库。

**修复**：不是简单"加大上限"（会撞嵌入上限），而是：

1. **等级软边界**：`a）危急 / b）严重 / c）一般` 在块较大时作为软边界切开，让危急/严重/一般不混块、也不硬拆；
2. **size 降到 400**：正文上限 400 字 + 块头（章节路径）约 100 字 ≈ 500 字，正好贴着嵌入上限。

**教训**：**切分粒度必须和嵌入模型的 max 长度对齐**。先查模型上限（512 token），再反推正文上限，而不是拍脑袋定 700。否则"超长"不是检索不准的问题，是内容被无声截断。

---

## 坑 4：OCR 乱码行难以识别（残留问题）

**现象**：清洗后仍残留少量乱码，如 `本二内内A83`、`Éx-28a zeme`、`24RECe`。

**根因**：

- 带重音拉丁字母（É）会被 `isalnum()` 判成"合法字符"，乱码率算不出来；
- 纯中文乱码（`本二内内A83`）本质是"字字都合法但连起来没意义"，**无法用字符规则区分**，只能靠语言模型。

**修复**：加了"**整行无中文 + 含 ≥3 连续字母**"判乱码的规则（抓住 `Éx-28a`、`24RECe` 这类），纯中文乱码暂时接受少量残留。

**教训**：**OCR 乱码有两类，一类能规则滤、一类滤不了**。别追求 100% 干净，先把大头（广告页/水印/拉丁乱码）滤掉，残留交给后续（人工抽检或语言模型）。

---

## 坑 5：中间标题单独成空块（孤儿块）

**现象**：结构切分早期，`4.1`、`4.1.1` 这种只有标题、下面直接是下一级标题的"中间标题"，被单独切成一个没正文的空块。

**根因**：把每个编号行都当硬边界。

**修复**：改成"**章节路径**"机制——中间标题只更新路径（`4 缺陷分类 / 4.1 架空线路 / 4.1.1 杆塔`），不单独成块；只有叶子章节（`4.1.1.1 杆塔本体`）才带着正文成一个块。块头带上完整路径，检索出来自足。

**教训**：**结构有层级，标题也有层级**。中间标题是"上下文"，不是"内容"，不能和叶子章节一视同仁。

---

## 坑 6：嵌入语义匹配伪升级（定级匹配）

**现象**：把缺陷库定级从字符 bigram 升级到嵌入语义匹配（bge-small 余弦相似度，业界主流），压测 500 样本：bigram 命中率 **71%**、误判 0，嵌入匹配命中率仅 **2%**、98% 降级。

**根因**：嵌入语义相似度把"绝缘电阻不合格"和"电容量不合格"这类**细微但关键**的差异抹平了——两者都含"不合格""试验数据超标"，语义模型判成高度相近，query 同时高相似度命中多条不同条目 → 跨等级歧义 → 降级。

**修复**：回退到 bigram 字面匹配。嵌入模块（`defect_embeddings.py`）保留但标注"不适用定级"，改用于未来的"口语化输入归一化"。

**教训**：**"业界主流"不等于"适合你的场景"，压测比主流重要**。语义匹配适合开放问答（同义不同词），精确匹配适合规则定级（细微差异必须分清）。电力缺陷是规范化术语、字面即标准，且"无法继续运行（危急）vs 可短期维持（严重）"这种差异是致命的——bigram 精确匹配反而对。这个负结果是压测救回来的，如果盲目上嵌入匹配，线上会大范围降级。

---

## 切分原则（总结）

1. **语义完整**：一个 chunk 是一个完整语义单元（一个章节/一个缺陷部位），不拦腰截断；
2. **上下文自足**：chunk 带完整章节路径做块头，单独检索出来也能看懂；
3. **粒度对齐嵌入上限**：正文 ≤400 字 + 块头 ≈500 字，贴着 bge-small-zh 的 512 token；
4. **不混类**：危急/严重/一般阈值放在一起（供定级比较），只在大块时按等级软切。

## 怎么保证"切分切好了"

分两层指标：

**结构性指标（能自动算，`chunk_metrics`）**：孤儿块 = 0、带路径比 ≥ 95%、超嵌入上限比 < 5%。这层能抓住"明显切错"（空块、无上下文、截断）。

**效果指标（金标准，`scripts/eval_retrieval.py`）**：Recall@K —— 用问答集（`eval/qa_set.py`，12 题起步）向量检索，看正确 chunk 是否进 top-K。**Recall@5 ≥ 80% 算合格**。结构性指标只是"必要不充分"，最终以 Recall@K 为准。
